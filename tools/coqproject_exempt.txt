# Ladder boards that are PARTIAL by construction: each stops before the
# machine-level theorem because an arm of the CLOSURE has no chain.  Every
# [sound_*] lemma in them is still a theorem -- the file's own header says how
# many of the certificate's arms were re-derived, and for several it is all of
# them.  Do not read that count as the reason: the certificate's arms and the
# closure's CLASS arms are different sets.  closure_data builds the class arms
# fresh from the family, and they are what fails.
#
# emit_ladder.py writes the reason into the .v file and there are exactly two:
#
#   line 381  interior arm: no chain at any threshold 0..3 and stride 1..4
#   line 431  fill arm: no chain at any threshold 1..3, stride 1..4 or copy split
#
# NINE stop on the INTERIOR arm and all nine rows are still core; between them
# they carry five 0RB shadows, so this list is 14 of the residue's rows and the
# densest bucket in it.  TWO stop on the FILL arm and neither row is core any
# more, so they are worth nothing but are kept as the fill twin of the
# question.  Wave 4l's shared arm indexing removed the older ClassSucc reason,
# so do not re-file any of these under 4h(a); wave 4p replaced that stale note
# inside all nine interior files with the measured reason, one per half.
#
# RE-MEASURED, wave 4p: **the nine are not one bucket, and the shared refusal
# line is the only thing they share.**  armprobe.py says 5 of 9, and neither
# half is what LADDER_PLAN 5 read off the failure text.
#
#   * FOUR are base-2 (the 1RB1LA/1RB0LD rows).  Their class fits -- the same
#     single (Binary, 1) class a boarded row uses -- and their configuration
#     is clean.  The interior arm's cost over the flat indices is 2, 6, 12,
#     20, 30, 42, ... resp. 12, 18, 26, 36, 48, 62, ...: a SECOND difference
#     of exactly 2, so quadratic in the run length.  A strided arm is one
#     chain repeated and no arithmetic progression makes a quadratic affine,
#     which is why every threshold and stride fail together.  LADDER_PLAN 5's
#     non-affine carry ripple: **CONFIRMED, and now measured.**  It agrees
#     with docs/QUAD_TERMINAL_MEASUREMENT.md, whose two rows are two of these
#     four.  These four are not coming back without a new arm shape.
#
#   * FIVE are FIBONACCI (the 1RB--- rows), and **their arms derive.**  Two
#     classes -- 1^n ++ [1;0] -> 0^n ++ [1;1] and [0] ++ 0^n -> [1] ++ 0^n --
#     cover every interior successor, and both arms chain with costs whose
#     first differences are constant.  The carry ripple here IS affine.  What
#     blocks them is the NUMERATION: Fam has no weight field, fam_value is
#     val_pos and fam_of_value divides down fm_b, and these counters spell
#     2, 3, 5, 8, 13, 21 members at widths 1..6.  They are LADDER_PLAN 4m's
#     five, filed here under the wrong reason, and they need 4m's
#     Fibonacci-rank constructor -- not an arm.
#
# Wave 4n's one-cell far-side reading is REAL on two of the four base-2 rows
# (1RB1LA_1LC0RD_0RA0LC_0LA1RD and 1RB0LD_0LC0RB_1LA1RC_0RC1LD): with the
# certificate's other_side_cells every flat arm lands off the rhs, with the
# boot's every one derives.  It does not rescue them -- the strided arm is
# quadratic either way -- but it is why their refusal text differs.
#
# Reproduce all of it with
#   python3 tools/ladder/armprobe.py tools/ladder/num59_after.jsonl --selftest
#   python3 tools/ladder/armprobe.py tools/ladder/num59_after.jsonl \
#           --rows tools/ladder/interior9_rows.txt
# and see tools/ladder/interior9_probe.{jsonl,log} for the committed run.
#
# They are kept as the record of where each row stops.  When a row's arm
# lands, its board finishes and moves into _CoqProject -- delete the line here
# rather than leaving both; check_coqproject.py fails on a line that does.
